# EdgeMind 有界多 Agent、记忆网络与 ToT 规划规格

日期：2026-10-10  
状态：待用户审阅  
版本：MVP 1

## 1. 目标与范围

在现有 EdgeMind Harness 上增加可审计、可评测的多 Agent 协作能力，并将记忆关系与有限候选计划搜索接入现有长程任务、四层记忆、工具权限和质量闭环。目标是让复杂任务能按职责拆解、基于证据执行、检查结果并沉淀可审核经验；简单请求继续使用现有单 Agent 路径。

本规格不引入任意 Agent 间自由对话，不保存或展示模型完整思维链，不允许 Agent 自主修改代码、批准记忆或执行未确认的副作用工具。

## 2. 设计决策

- 首版采用单协调器加职责明确的逻辑 Agent，共享现有 Provider/模型配置；不要求多模型或新增模型 API。
- 首版按顺序执行 Agent handoff，使用有版本的角色提示、输入/输出契约和独立能力范围。并行执行留给后续只读、互相独立的子任务。
- 简单任务保留单 Agent；多步骤、需要多个信息源或明确计划的任务才进入多 Agent 编排。
- ToT 实现为有预算的候选计划搜索，而非展开或展示原始模型思维过程。
- 记忆图以现有四层记忆为节点，SQLite 关系表为边；不替换现有记忆生命周期，也不首期引入图数据库。
- 所有新能力可由确定性 Provider 与工具 fixture 测试；默认评测不访问真实 DeepSeek、MCP 或外部网络。

## 3. 编排与 Agent 职责

建议新增独立 orchestration 模块，并由现有 AgentService 作为兼容入口委托复杂任务；不得继续把全部角色流程堆入 AgentService 单体方法。

执行路径：请求分类 → Coordinator 决定单 Agent 或协作模式 → Planner 生成任务步骤及候选计划 → Researcher 检索已批准记忆、记忆关系及 RAG 证据 → Executor 按策略调用允许的内置/MCP 工具 → Reviewer 检查目标完成度、证据与引用、工具结果和安全约束 → Coordinator 汇总最终答案、写运行事件并创建待审核记忆候选。

角色契约：

- Coordinator：创建 run、分配预算、维护状态、授权 handoff、处理失败与最终输出；不绕过工具或记忆治理。
- Planner：输出通过 schema 校验的子目标、依赖关系、成功条件、所需证据/工具及风险摘要。
- Researcher：只读检索并返回 memory/evidence ID、来源和相关性摘要，不编造引用，不写长期记忆。
- Executor：仅可使用本轮由策略和工作流共同允许的工具；MCP 副作用调用沿用提案与人工确认机制。
- Reviewer：输出通过项、问题和建议的下一步；最多触发一次有界修订，不直接改变活动策略或批准记忆。

每次 handoff 采用显式结构化对象（run/task ID、角色、目标、输入证据 ID、允许工具、预算、输出 schema、状态），拒绝未知字段或超限 payload。角色失败、格式无效或超预算时记录失败类别，并退回安全的单 Agent/澄清路径；涉及副作用的调用不得因 fallback 自动执行。

## 4. 有界 ToT 计划搜索

复杂任务的 Planner 最多提出 3 个候选计划。每个候选包含步骤、依赖、预期证据、预期工具、风险和估算成本。系统先校验 schema、步骤数、工具 allowlist、依赖无环和总预算，再按固定 rubric 评分：目标覆盖度、可用证据、工具可用性、安全风险、步骤/调用成本。安全条件是硬门槛，不可由其它分数抵消；平分时选择步骤更少的方案。

首版最多一个规划阶段、一个执行阶段和一次 Reviewer 修订；默认最多 5 个子步骤、3 个候选计划及受策略配置的模型/工具调用预算。预算耗尽时停止规划并返回已有结果、未完成项和原因。轨迹只保存候选计划、评分维度、选中理由摘要及实际行动；不存储或渲染完整 CoT/scratchpad。

## 5. 记忆关系网络

保留 Working、Episodic、Semantic、Procedural 节点和 pending/approved/rejected 生命周期。新增有向关系边，初始关系类型限定为 `derived_from`、`supports`、`contradicts`、`used_in`、`similar_to`。边记录 source/target ID、关系类型、置信度、来源 run、审核状态和创建时间；引用的节点必须存在，非法层级/关系/自环/重复关系应拒绝或幂等处理。

边默认从审核通过的记忆、证据和任务结果创建；模型提出的边只作为 pending 候选。删除/拒绝节点时按明确规则移除或标记关联边，不得使查询返回悬空内容。查询流程从当前 FTS/BM25/可选向量检索产生种子，仅扩展 approved 边，最多 1 跳并设置节点数上限；融合基础相关性、关系类型权重、来源可信度和时效，输出节点及路径说明，允许关闭图扩展回退到现有检索。

## 6. 轨迹、界面和质量评测

运行轨迹记录分类结果、采用模式、角色 handoff、输入输出 ID 摘要、候选计划及评分摘要、记忆图扩展路径、工具提案/结果、Reviewer 结论、阶段耗时和 token usage（Provider 提供时）。继续使用字段白名单、截断和密钥/媒体脱敏；不记录 API key、原始媒体字节或完整隐藏思维链。

界面应简洁展示当前任务采用单 Agent 或协作模式、阶段状态、角色交接、计划选择依据、证据/记忆来源、工具确认状态与失败原因。详细轨迹折叠显示，不把内部思维文本冒充可解释性。

Agent 回归集新增多 Agent 案例：适合单 Agent 的简单请求、长任务拆解、记忆关系带来的证据补充、候选计划选择、Reviewer 发现证据缺口、工具越权拒绝、模型/工具失败和预算耗尽。报告至少比较单 Agent baseline 与协作模式的任务案例通过率、引用/证据覆盖、工具 allowlist 合规（越权为 0）、记忆检索指标（有 gold 时）、运行时延和 token/调用成本。缺少 gold/usage 时显示 N/A。必须通过同一固定数据集回归；不能只以调用 Agent 数量作为成果。

## 7. 迁移、安全与兼容

采用 SQLite 显式向前迁移，现有数据库、任务、记忆、RAG、工具提案、MCP 确认和策略历史保持兼容；新功能默认关闭或仅对复杂任务路由开启。回滚代码/策略后，历史 run 和关系记录仍可读取。评测不得触碰正式任务和外部副作用工具。提示、网页内容、记忆和工具输出均视为不可信数据，不能升级成系统指令。

## 8. 验收标准

1. 简单请求走既有单 Agent 路径；复杂任务能生成有效计划并完成至少一次可追踪的角色 handoff。
2. 每个角色的工具权限受 allowlist 约束；越权请求被拒绝，副作用工具仍需人工确认。
3. ToT 候选数量、计划深度、修订轮数和调用量受限；无效计划、预算耗尽及 Agent 失败可解释且能安全退出。
4. 轨迹展示计划、证据、角色交接和评分摘要，不包含完整隐藏思维链或密钥。
5. 记忆边支持审核、查询、去重与节点删除一致性；待审核关系不参与正常检索。
6. 图扩展检索可解释、设有跳数/节点上限，并可回退至当前四层记忆检索。
7. Fixture 回归比较单 Agent 与多 Agent，报告质量、安全、延迟和成本；缺少标注时为 N/A。
8. SQLite 迁移从现有状态升级且不破坏现有功能；现有测试通过并新增边界、安全、回归测试。
9. README 说明启用方式、预算/指标含义和能力限制；不宣称未经测量的性能提升。

## 9. 分阶段交付

- Phase 1：协调器与 Planner/Researcher/Executor/Reviewer 结构化顺序 handoff、轨迹和 fixture 测试；简单问题仍单 Agent。
- Phase 2：SQLite 记忆关系表、审核流程、有限图扩展检索和可视化解释。
- Phase 3：有限 ToT、单 Agent/多 Agent 固定集对比和质量门禁。
- Phase 4（候选）：只对相互独立的只读子任务并行；须以质量不退化且成本可接受的评测结果为前提。

前三阶段纳入本次项目目标；并行执行为后续候选，不纳入首期验收。
