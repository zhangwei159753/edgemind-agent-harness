# EdgeMind Agent 质量与经验闭环规格

日期：2026-10-10<br>
状态：待用户审阅<br>
版本：MVP 1

## 1. 项目目标与定位

EdgeMind 的核心不是工具/API 集成集合，而是一个可复盘、可评测、可受控改进的通用长期任务 Agent Runtime。它要回答三个工程问题：

1. 一次任务为什么成功或失败，Agent 当时依据了哪些记忆、证据和工具结果？
2. 记忆是否真正改善了任务结果，还是只增加了上下文噪声？
3. 一项 Agent 策略变更是否通过可重复评测，是否值得启用，失败后如何回滚？

项目面向单用户本地知识工作和开发者长期任务，支持任务续接、多模态输入、四层记忆、个人 RAG 和受控工具。它与 converter-engineering-copilot 的边界是：EdgeMind 研究通用 Agent 运行质量、长期记忆与受控改进；Converter Copilot 处理电力变换器专业问题、工程证据和垂直工作流。

简历与演示只陈述实际实现和测量结果，不把调用模型、引入开源组件或未经验证的“自进化”描述成自主 Agent 创新。

## 2. 设计原则

- **证据先于主张：**质量报告必须能追溯到 run、评测案例、数据集版本和策略版本。
- **明确区分执行与评估：**在线任务和离线回放分开；评测环境默认使用固定工具夹具，不执行外部写操作。
- **改进受控：**反馈可以生成经验/策略候选；候选经过评测与人工审核后才能成为活动版本。
- **记忆有来源和效用：**记忆记录来源、审核状态、被检索情况与用户对效用的反馈；系统不因一次低分自动删除记忆。
- **可重复而不伪装确定性：**记录模型、参数、提示版本、工具夹具和输入快照；模型本身可能非确定，报告需显示运行次数与方差。
- **最小兼容迁移：**SQLite 新增表或显式版本迁移，不破坏现有 Harness、RAG、记忆、媒体与 MCP 数据。
- **本地优先和密钥隔离：**密钥只在服务端 provider 层使用；数据集、轨迹、导出和报告不包含凭证。

## 3. 当前基础与缺口

当前项目已经有：

- 持久化任务、checkpoint、运行事件和可审核的四层记忆；
- Agent 多轮工具调用、MCP 副作用确认、技能 allowlist；
- 记忆检索命中和阶段耗时轨迹；
- 面向 RAG 的离线评测及配置实验入口。

当前缺少 Agent 级的固定评测案例格式、运行回放和策略对比；任务结果与记忆效用缺少结构化标注；Agent 策略版本没有端到端的评测、晋升和回滚证据链。因此当前更像“具备多项功能的 Agent Demo”，本规格聚焦补齐质量闭环。

## 4. 用户与核心流程

目标用户是需要跨会话推进工作、并希望了解 Agent 是否有效的本地用户/开发者。

核心流程：

1. 用户选择或创建任务，Agent 读取 checkpoint、批准记忆和知识库证据并运行。
2. 每轮生成关联任务、运行、策略版本、检索记忆、工具调用、证据与结果的运行记录。
3. 用户对任务结果标注成功、部分完成或失败；可标注相关记忆有帮助、无帮助或不确定，也可提交纠错。
4. EdgeMind 将反馈和运行失败归类，生成可审核的记忆候选或策略改进候选。
5. 用户用固定评测集比较当前策略与候选策略；报告同时呈现质量、安全和效率指标及逐案差异。
6. 通过质量门槛的候选由用户显式晋升；出现回退或质量退化时可恢复先前策略。
7. 后续任务沿用活动策略，并继续积累新的运行证据。

## 5. 核心架构

### 5.1 Agent Run Ledger

扩展现有 Harness event/run 记录，统一关联：

- task_id、run_id、创建时间、完成状态和用户结果标注；
- 活动 Agent policy ID/version 与不可变的策略快照/哈希；
- 模型 provider/model、可用的参数和 usage 元数据；
- 输入类型与脱敏摘要，不保存原始媒体字节；
- 检索到的 memory IDs、层级、分数、排序理由；
- RAG corpus/version/citations；
- 工具调用 ID、工具名、参数摘要、结果状态、耗时、来源和确认状态；
- 最终结果与失败类别；
- 用户纠错、任务结果和记忆效用标注的关联。

访问令牌、API key、Authorization 头、原始音视频和不受控网页内容不得进入此账本。敏感字段按白名单序列化，限制每类内容长度。

### 5.2 结构化反馈与错误归因

每个已完成 Agent run 可以标注：

- 任务结果：success、partial、failure、unrated；
- 主要失败类别：planning、memory、retrieval/evidence、tool selection、tool execution、answer quality、provider/network、user input 或 other；
- 可选说明与纠正内容；
- 本轮实际使用的记忆是否 helpful、not_helpful、uncertain。标注关联具体 memory IDs，避免把整轮成败误算为每条记忆的效用。

标注必须允许跳过和修订，保留审计历史。自动分类只提供建议，不代替用户确认。

### 5.3 记忆效用与治理

保留现有四层记忆和 pending/approved/rejected 生命周期，新增可解释的效用信号：

- memory exposure：在哪些 run 中被检索并实际进入模型上下文；
- memory feedback：用户对具体记忆的帮助程度标注；
- memory provenance：来源 run/task、审核人/状态、创建原因；
- candidate action：保留、编辑、合并建议、冲突复核或停用建议。

评分只作为审核排序信号。一次负反馈不能自动删除/降权已批准记忆；重复低效、冲突或用户纠错才形成候选，必须让用户确认。初版不自动推断“记忆真伪”，不以模型自己生成的文本作为已验证事实。

### 5.4 Agent Evaluation Runner

新增与 RAG EvaluationRunner 分开的 AgentEvaluationRunner，复用现有评测报告风格，但不混淆 Agent 与 RAG 指标。

评测数据集采用版本化 JSONL，每条案例包含：

- example_id、任务说明、输入/历史上下文和可选记忆夹具；
- 可用工具及固定工具响应夹具；
- 期望任务结果类别或检查器；
- 期望/禁止工具调用规则；
- 可选的必需证据/引用 ID；
- 安全约束与案例标签。

评测默认隔离在线 SQLite 主状态，使用临时存储、确定性 provider stub 和工具夹具；不调用真实 MCP 副作用工具。可选 live model run 必须由用户显式触发，单独标注 provider/model、数据集版本、时间、采样参数和外部调用状态。

报告至少区分：

- 用户标注任务成功率：有结果标注的案例中 success 的比例；partial 单独报告，unrated 不进入分母；
- 工具选择/执行：工具选择符合 allowlist 的比例、工具成功率、拒绝/越权调用数；
- 记忆：检索 Precision@K/Recall@K（仅有人工 gold 标签时计算）、用户 helpfulness 比例（仅对有标注 exposure 计算）；
- 证据：必需引用覆盖率（仅对配置了引用 gold 的案例计算）；
- 效率：端到端耗时分布、模型/tool 阶段耗时、usage/token（provider 有返回时才计算）；
- 稳定性：重复运行次数、关键指标均值/离散度、失败案例与差异清单。

没有标签或 provider usage 的指标显示 N/A，不以 0 替代，也不伪造评测结果。

### 5.5 Agent Policy 实验、晋升与回滚

AgentPolicy 是受 schema 校验的声明式配置，首期只允许调整：

- system/developer prompt template 版本或文本引用；
- memory retrieval 的 top-k、层级权重、时间衰减及过滤配置；
- 已注册工具的 allowlist 和有界工具轮数；
- 输出约束/检查器配置。

配置禁止 Python、Shell、动态导入、未注册工具、任意代码和秘密值。每个候选包含变更说明、创建来源、baseline policy、数据集版本和评测结果。

晋升门禁至少要求：

1. 全部安全不变量通过，越权调用与确认绕过数必须为 0；
2. 在指定的关键指标上达到用户配置的非劣/提升门槛；
3. 效率指标没有超过显式预算；
4. 报告中不存在未审阅的失败案例；
5. 用户显式批准。

活动策略切换写入版本历史，并可原子回滚到上一个活动版本。评测失败不得改变线上活动策略。

## 6. UI 与操作方式

Agent 页面显示当前活动策略版本、最近 run 结果标注入口和 memory feedback；避免把所有原始事件堆在聊天内容中。

新增“Agent 质量”工作区：

- 数据集列表、案例标签和数据集版本；
- 运行离线评测、比较 baseline/candidate；
- 展示总指标与逐案例差异、工具/记忆/引用失败原因；
- 建立策略候选、查看变更摘要、提交审核、晋升或回滚；
- 导出脱敏 JSON 报告。

展示页明确区分本地 mock 评测和真实 provider 评测；真实 provider 调用需要用户手动启动。

## 7. 隐私、安全和隔离

- 默认本地单用户；不增加云端账号、远程数据上传或常驻后台任务。
- 评测工具使用 fixture；任何有副作用工具均禁止进入自动回放。
- 运行和报告采用字段白名单与长度上限；对 key/token/Authorization 等模式执行防泄漏检查。
- 策略、Skill、数据集都通过 schema 校验；不可执行动态代码。
- 网页内容、模型输出和用户附件是数据，不是系统策略指令。
- 对任务删除、记忆删除和用户数据导出沿用现有控制，新增表具备清晰保留/删除关联规则。

## 8. 非目标

- 自动训练或微调基础模型；
- Agent 自主修改源码、依赖、策略或用户的已批准事实；
- 无监督无限循环、自主后台任务或自动调用有副作用工具；
- 用模型自评代替用户/人工 gold 标签；
- 将 RAG 检索指标直接解释成 Agent 任务成功率；
- 新增第二个电力变换器领域工作台；
- 声称具体效果提升、准确率、成本节省或性能数据，除非由保存的评测报告支持。

## 9. 验收标准

1. 一个 Agent run 可关联活动策略、记忆命中、RAG 证据、工具调用、耗时和用户结果标注，并可导出脱敏报告。
2. 用户可标注任务结果与具体记忆效用；unrated/uncertain 数据不会被错误计入正负指标。
3. 每条评测案例可通过 JSON Schema/等价校验；非法工具、动态代码字段、秘密值和缺少必要标识会被拒绝。
4. AgentEvaluationRunner 能在隔离临时存储中用 provider stub 和工具 fixture 重放案例，不改变用户正式任务/记忆/MCP 状态。
5. 报告计算上述可用指标，缺少 gold 或 usage 时明确显示 N/A；逐案例可回溯失败原因。
6. baseline 与候选策略可基于同一固定数据集比较；安全门禁失败时不可晋升。
7. 用户批准后活动策略版本原子切换；回滚后旧版本继续可用，版本历史可审计。
8. 真实 provider 评测仅在用户显式操作时运行，并与 mock 报告分开标识。
9. 现有 Harness、RAG、任务续接、多模态输入、MCP 确认和记忆审核保持兼容；数据库迁移可从旧状态无损升级。
10. 所有演示指标可从项目内的版本化数据集与生成报告复现；README 给出步骤和指标定义。

## 10. 首期交付边界与后续候选

首期规格目标是先搭出完整但最小的证据闭环：结构化 run/反馈、版本化 Agent eval dataset、隔离回放、baseline/candidate 报告和策略门禁。记忆效用标注先落入 run ledger；自动合并/冲突检测、个性化策略推荐和后台持续评测可以在首期评审后再拆分，不作为初版通过条件。

首期必须包含至少一个版本化小型 Agent 场景集，案例覆盖长程任务续接、记忆相关性、工具选择/确认边界、RAG 引用和失败恢复。数据集只作为回归样例，不宣称具有统计代表性。
